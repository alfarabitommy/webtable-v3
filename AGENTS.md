# AGENTS.md — Synapse (webtable)

**Synapse** — Indonesian, mobile-first AI GPU rental / GPUaaS investment platform: rent GPU nodes for daily ROI, single authoritative wallet ledger (`wallet_ledger`), multi-level agency/affiliate + promoter system, manual-QRIS deposit gateway, e-wallet-only payouts, admin command center.

## Project

- **Stack:** CodeIgniter 3 (PHP 8.3.6 verified; CI3 `composer.json` is stock framework metadata — **no runtime Composer deps, no build step**), MySQL/MariaDB (`db_webtable`), Vanilla JS (no bundler), Tailwind CSS (Play CDN) + Font Awesome via CDN. Admin surfaces use the same stack; **no framework files under `system/` may be modified** except the one pinned compatibility fix below.
- **Entry point:** `index.php` (CI3 front controller). Clean URLs (`index_page=''`) via `application/config/routes.php`; Apache rewrite in `.htaccess`, nginx in `nginx-rewrite.txt`. `base_url` comes from `APP_BASE_URL` (env) with a committed dev fallback.
- **UI language:** member-facing surfaces are **dual-language EN/ID** (plan/94 — `en` is the default for new visitors, `id` secondary); the **admin panel stays 100% Indonesian** (invariant L1 — `Admin`/`Admin_auth` never call `i18n_apply()`). **All money is IDR only** (no foreign currencies at any layer) and is never localized — `Rp` + `number_format(id-ID)` in both idioms (L6).
- **Business spec is authoritative in `docs/`:** `1_PRD.md` (v5.0 — exact business logic; **note §G wage tiers are stale, code wins**), `2_ERD.md`, `3_ROADMAP.md` (v6.0 — strict agent rules; **stale**: Phase 1 still lists removed artifacts and phases 102–104 have no section), `4_UI_UX_GUIDELINES.md`, `5_AUDIT_REPORT.md`. When a doc and the code disagree, **code is authoritative** (precedent: plan/80 P5 wage tiers).

## Architecture

- **`application/core/MY_Controller.php`** — base for member controllers. Fixed statement order after `parent::__construct()`, do not reorder: **① `maintenance_gate()`** (plan/95) → **② `SET time_zone = '+07:00'`** WIB pin (M2, first DB statement, forces lazy connection) → **③ `i18n_apply()`** (plan/94 F1) → **④ login guard** (`user_id`, redirect `login`; `auth` exempt) → **⑤ lazy sweeps + reads**: re-read user row (ban lockout / forced password change) → `Rental_model::expire_user_rentals()` (M3) → `Wallet_model::expire_user_deposits()` (plan/102) → `Wallet_model::get_balance()` → `Notification_model` counts. Injects `global_balance`, `global_unread_count`, `global_notifications`.
- **Controllers (member):** `Auth` (register/login/logout/change_password + native SVG CAPTCHA + phone normalizer; `auth/refresh_captcha` AJAX), `Home`, `Marketplace`, `Rentals` (checkout/claim), `Wallet` (**`index`, `topup`, `pay`, `confirm_payment`**, `simulate_payment`, `withdraw`, `process_withdraw`, `simulate_wd_approve`, `bind_bank`), `Team` (affiliate hub + `promoter_claim`, `claim_level1`, `claim_wage`), `Profile`, `Help`, `Notification` (history page), `User` (`read_notifications` AJAX), `Lang` (dual-language switcher, extends `CI_Controller` so it works pre-login).
- **Controllers (admin):** `Admin` + `Admin_auth`, cloaked login at `/control-panel` (route `'control-panel' => 'Admin_auth/login'`), guarded by `admin_id` session (never shared with `user_id`). `Admin` also exposes queues/CRUD: deposits approve/**decline**, withdrawals, `promoter_claims`, `products` (+`create`/`update`/`toggle_status`), `ewallet_providers` (+`create`/`update`/`toggle_status`), `settings`/**`qris_settings`**/`financial_settings`, users (`user_detail`, `update_user`, `toggle_ban`, `toggle_promoter`, `inject_balance`, `inject_rental`, `cancel_rental`, `adjust_time`, `reset_password`, `reset_ewallet`, `create_user`), `toggle_registration`, `toggle_maintenance`, `expire_expired_rentals`, `alerts_poll`, `audit`, `analytics`/`chart_data`/`user_xray`, `export_csv`.
- **Models — all DB access lives here** (no SQL in controllers/views). `Wallet_model` is the **sole writer of money and of `bank_accounts`** (`_post()` is the single credit/debit choke-point; `bind_user_ewallet()`/`unbind_user_ewallet()`/`reassign_provider_name()`/`get_user_ewallet()`); `Ewallet_model` is the sole writer of `ewallet_providers`; `Rental_model` owns checkout/claim/expiry/rebate; `Promoter_model` owns omzet-burn claims; `Admin_model` owns admin queues/CRUD/`get_alert_counts()`/`is_product_image_referenced()`; `Audit_model`, `Rate_limit_model`, `Notification_model`, `User_model` (`LEVEL1_BONUS`, `WAGE_TIERS`), `Product_model`.
- **Ledger:** `wallet_ledger` is the **sole authoritative transaction ledger** — immutable `credit`/`debit` rows with deterministic `transaction_id` (`ROI-{rental_id}-D{n}`, `RBT-{rental_id}-L{tier}`, …). The legacy double-entry `transactions` table was decommissioned (M6, plan/68–69). All money moves run inside ACID transactions (`trans_begin/commit/rollback`) with a `SELECT … FOR UPDATE` anchor on `users`; balance = `SUM(credit) − SUM(debit)` via `Wallet_model::get_balance()`.
- **Helpers are choke-points** (autoloaded, pure, `function_exists()`-guarded) — one source of truth per rule: `i18n_helper` (language resolution/application), `maintenance_helper` (gate + JSON parity detection), `captcha_helper` (SVG alphabet/render), `product_image_helper` (basename allowlist + `null` fallback contract), `wa_group_helper` (WhatsApp invite canonicalization), `ewallet_helper` (phone normalize/validate/mask), `referral_helper` (invite-code normalize/validate/prefill precedence), `api_helper` (JSON envelope), `ratelimit_helper`.
- **Views:** member pages use `templates/header.php` + `templates/bottom_nav.php`; admin uses `admin/templates/*`. Member header holds **exactly three groups — Brand, Balance Pill, Notification Bell** (plan/100); Language/Theme controls live on the Profile page ("App Preferences"). Mobile-first `max-w-[480px]` shell.
- **Admin real-time alert center (plan/94 F2):** `GET /admin/alerts/poll` → `Admin::alerts_poll()` → `Admin_model::get_alert_counts()`; client in `views/admin/templates/footer.php` (`window.AdminAlerts`, 25 s polling, pause when hidden, chime only when `total_urgent` rises, `Cache-Control: no-store`, no audit row).

## Conventions & Standards

- Every PHP file starts with `defined('BASEPATH') OR exit('No direct script access allowed');`.
- **SQL only in models**, with bound params (`$this->db->query("… ?", [$id])`); query builder is acceptable (see `Admin`). No SQL in controllers or views (roadmap rule 2).
- **Dual-auth hard separation:** `user_id` vs `admin_id` sessions — never shared; admin routes redirect to `control-panel` when `admin_id` is missing.
- **API responses (mandatory, M9/P7 — plan/76–77):** every AJAX/JSON endpoint responds through `application/helpers/api_helper.php` (`api_success()` / `api_error()`) using the canonical envelope `{success, message, data, code?, errors}` **plus** root legacy keys where the frontend still reads them — never a hand-rolled `{success,…}` / `{error,…}` shape. AJAX 404/error/exception responses are normalized to clean JSON by `application/core/MY_Exceptions.php` (`_wants_json()`), so `fetch().json()` never parses HTML.
- **Integer IDR discipline (mandatory, M8 — plan/74–75):** validate monetary inputs server-side against `^[1-9][0-9]*$` before any model call; all credits/debits pass the single `(int)` choke-point + positivity assertion in `Wallet_model::_post()`; fee arithmetic uses `intdiv()` — never float division. MySQL keeps `DECIMAL(15,2)` for compatibility, but `get_balance()` / `lock_and_get_balance()` return `(int)`.
- **Money display:** PHP `number_format($val, 0, ',', '.')` with `Rp ` prefix; JS `Intl.NumberFormat('id-ID', { style: 'currency', currency: 'IDR', maximumFractionDigits: 0 })`. **Never** put money/numbers in the language dictionaries (L6; gate P3 enforces).
- **i18n rules:** member copy goes through `lang('<key>')`; EN and ID dictionaries must stay **1:1 with identical key sets (currently 602 each)** and identical values are forbidden outside the auditor's allowlist. Dynamic JS strings are passed via `window.SYNAPSE_I18N`. Admin copy is Indonesian-only (L1) — never route admin through `i18n_apply()`. Run both `scripts/audit_i18n_*.php` gates after any copy change.
- **Route registration:** add an explicit `$route[...]` in `application/config/routes.php` for every new pretty URL **and for multi-segment sub-paths** (`translate_uri_dashes = FALSE`); otherwise CI3 maps the extra segment as a method argument. One-off AJAX methods (`auth/refresh_captcha`, `admin/toggle-ban`, `admin/reset_ewallet/{id}`) intentionally work as direct method URLs.
- **Schema/state machine changes are two-file changes:** `database.sql` (canonical DDL, with a migration note for live) **and** `database_seed.sql` where seed rows are involved, plus an idempotent `scripts/migrate_<NNN>_*.php`. Verify live with `--verify`.
- **Business state machines (see `docs/1_PRD.md` before touching money):** deposit `pending → waiting_approval → success` with `failed`/`rejected`/`expired` retention branches (plan/102: unique 3-digit code 100–999, `reserved_code_key` UNIQUE, expiry window default 60 min, credit = **principal + code** with the fee withheld, one live deposit per user); single pending withdrawal; withdrawal window **Mon–Sat 07:00–19:00 WIB**; integer fee tiers in `application/config/withdrawal_fees.php` with `system_settings` overrides (half-open `[min, max)` tiers — boundary amount takes the cheaper tier).
- **E-wallet payout contract (plan/106):** `bank_accounts` structure is frozen — `bank_name` = provider name from the catalog, `account_number` = canonical e-wallet phone (`^08[0-9]{8,11}$`), `account_holder` = owner name, `is_primary` = **active-binding flag** (`1` bound, `0` archived). Admin reset **archives, never deletes** (FK `fk_withdrawals_bank` is `ON DELETE RESTRICT`). Withdrawals verify ownership + binding status again inside the TX (`no_ewallet`).
- **Helper-first rule:** when you add a cross-cutting rule (validation, normalization, formatting, external-link handling), put it in a single `application/helpers/*_helper.php` choke-point and call it from controller/view/admin/CLI — do not re-implement inline.
- **Plan discipline:** work on per-phase branches per `docs/3_ROADMAP.md`; commit messages in Indonesian; keep `plan/NN_*_PLAN.md` + `plan/NN_*_SUMMARY.md` as the authoritative change record and refresh `docs/` when an invariant changes.
- **Framework compatibility rule (PHP 8.3):** the CI3 pagination root fix at `system/libraries/Pagination.php` (~`:526`, `(string)` cast so `ctype_digit(null)` is never hit when the `per_page` query segment is absent) is **required on PHP 8.1+ and must never be reverted** by a framework sync/upgrade (plan/80 follow-up). `application/config/mimes.php` **must** keep `'webp' => array('image/webp')` or `Upload::is_allowed_filetype()` rejects every WebP (plan/104). The `User_model::LEVEL1_BONUS`/`WAGE_TIERS` const pattern likewise stays — amounts are centralized, never re-inlined.

## Agent Guardrails & Operating Rules

**Always**
1. `php -l` every new/modified PHP file before declaring done.
2. Run both `scripts/audit_i18n_*.php` gates whenever member copy, views, or `application/language/**` change — both must exit 0.
3. Add/keep the `$route[...]` entry for any new URL (including sub-segments) and register non-obvious AJAX endpoints explicitly.
4. Keep SQL in models, money moves inside a TX with `FOR UPDATE`, and every status flip conditional (`WHERE status='pending'` + `affected_rows() === 1`, M4).
5. Write an `Audit_model` row for every admin state change; read-only endpoints (`alerts_poll`) must **not** audit (A1).
6. Keep CLI scripts idempotent with `--dry-run` default and exit codes 0/1/2, and mirror any DDL into `database.sql`.
7. Report the verification you actually ran (command + observed result). Never claim a test suite ran.

**Never**
1. Never edit anything under `system/` except the pinned `Pagination.php` fix; never revert that fix or the `mimes.php` webp entry.
2. Never write SQL in a controller or view; never bypass `Wallet_model::credit()/debit()/_post()` or `Ewallet_model` to mutate money/catalog rows.
3. Never call `i18n_apply()` (or load `app_lang`) from admin code; never localize money/numbers; never hardcode member copy.
4. Never hand-roll JSON envelopes; never let an AJAX path return HTML.
5. Never hard-delete: GPU products, e-wallet providers, bank bindings, or ledger rows (archive/toggle instead).
6. Never commit secrets, a `live` `$active_group`, or a production `base_url`; never re-introduce the purged external CAPTCHA (M8).
7. Never touch `uploads/qris/*`, `uploads/products/*`, or `backups/*` as tracked content — only the `index.html` placeholders are tracked.
8. Never park scratch scripts, probes, or generated output in the repo — use `/tmp` and clean up.

**Sensitive / high-blast-radius files** — change with care and re-verify live behaviour: `application/config/database.php` (credentials), `application/config/config.php` (`base_url`, `encryption_key`, CSRF/session), `application/core/MY_Controller.php` (statement order is load-bearing), `application/models/{Wallet,Rental,Promoter,Admin}_model.php`, `application/config/routes.php`, `database.sql` / `database_seed.sql`, and `scripts/migrate_104/105/106_*`.

**Definition of done:** every modified PHP file lints clean; both i18n gates exit 0 when copy changed; the flow is exercised over HTTP (200/302 as expected) or via the plan's CLI harness; DDL changes exist in both `database.sql` and an idempotent migration that has been re-run to prove a no-op; `plan/NN_*_SUMMARY.md` records the change with its evidence; the final diff contains only intended changes.
