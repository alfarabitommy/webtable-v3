# AGENTS.md — Synapse (webtable)

**Synapse** — Indonesian, mobile-first AI GPU rental / GPUaaS investment platform: rent GPU nodes for daily ROI, single authoritative wallet ledger (`wallet_ledger`), multi-level agency/affiliate + promoter system, manual-QRIS deposit gateway, e-wallet-only payouts, admin command center.

## Project

- **Stack:** CodeIgniter 3 (PHP 8.3.6 verified; CI3 `composer.json` is stock framework metadata — **no runtime Composer deps, no build step**), MySQL/MariaDB (`db_webtable`; local dev box verified on MariaDB 12.3.2), Vanilla JS (no bundler), Tailwind CSS (Play CDN) + Font Awesome via CDN. Admin surfaces use the same stack; **no framework files under `system/` may be modified** except the one pinned compatibility fix below.
- **Entry point:** `index.php` (CI3 front controller). Clean URLs (`index_page=''`) via `application/config/routes.php`; Apache rewrite in `.htaccess`, nginx in `nginx-rewrite.txt`. `base_url` = `APP_BASE_URL` (env) **or the committed fallback `https://synapserent.com/`** (`config.php:26`; the dev/alternate URLs are commented out at `:27-28`) — always set `APP_BASE_URL` when working locally.
- **UI language:** member-facing surfaces are **dual-language EN/ID** (plan/94 — `en` is the default for new visitors, `id` secondary); the **admin panel stays 100% Indonesian** (invariant L1 — `Admin`/`Admin_auth` never call `i18n_apply()`). **All money is IDR only** (no foreign currencies at any layer) and is never localized — `Rp` + `number_format(id-ID)` in both idioms (L6).
- **Business spec is authoritative in `docs/`:** `1_PRD.md` (v5.6 — exact business logic; §G agency rewards are **dynamic** since plan/119 **and Bonus Pencapaian Tim is the SOLE agency achievement reward since plan/120**: tiers/amounts live in `system_settings.team_milestone_tiers` + `application/config/team_milestones.php`, no `WAGE_TIERS` const anymore), `2_ERD.md` (v5.6 — invariant list incl. K7/K8, CK1–CK8, MK1–MK8, W1–W5, L1R1–L1R6, SP1–SP12, and the **16-table** inventory), `3_ROADMAP.md` (v6.0 — strict agent rules; **stale**: Phase 1 still lists removed artifacts, though milestones 112–121 now all have sections), `4_UI_UX_GUIDELINES.md` (v5.3), `5_AUDIT_REPORT.md`. When a doc and the code disagree, **code is authoritative** (precedent: plan/80 P5 wage tiers).

## Commands

- **Lint (mandatory, roadmap rule 5)** — run on every new/modified PHP file:
  ```bash
  php -l <file>
  ```
- **i18n CI gates (mandatory after touching any view/controller copy or `application/language/**`)** — both must exit 0:
  ```bash
  php scripts/audit_i18n_parity.php      # EN≡ID 1:1, no leaks/no literals -> "LULUS"
  php scripts/audit_i18n_hardcoded.php   # member-surface hardcoded strings -> "0 temuan"
  ```
- **Local dev server** (from project root; pretty URLs need the rewrite config, cleanest via a `synapse.test` vhost):
  ```bash
  php -S localhost:8080
  # works out of the box in containers/sandboxes where `localhost` resolves to a
  # missing unix socket — force TCP + point at the DB you mean:
  DB_HOSTNAME=127.0.0.1 DB_DATABASE=db_webtable DB_USERNAME=root DB_PASSWORD=root \
    APP_BASE_URL=http://127.0.0.1:8080/ php -S 127.0.0.1:8080
  ```
- **DB selection** — `application/config/database.php` defines three groups and `$active_group` picks one: `local` (env `DB_*` → `root/root`, `db_webtable`), `dev` (`cmlh9365_synapse`), `live` (`gtwqzhzq_synapse`). **Both HEAD and the working tree ship `$active_group = 'live'` plus the production `base_url` fallback** (`config.php:26`), so any local run **must** override with `DB_HOSTNAME=127.0.0.1 DB_DATABASE=… DB_USERNAME=… DB_PASSWORD=… APP_BASE_URL=…` (each group reads those env vars first). **Never commit a switch to `live` or a production `base_url`.** Treat the local `db_webtable` as data you must not mutate while verifying — prefer a throwaway DB (see Testing).
- **Migrations / seeds** — every numbered script follows the same contract (`--dry-run` = default, `--apply`, `--verify`, idempotent, exit 0/1/2):
  ```bash
  php scripts/migrate_<NNN>_<name>.php --dry-run   # plan only, no writes
  php scripts/migrate_<NNN>_<name>.php --apply     # re-run must be a no-op
  php scripts/migrate_<NNN>_<name>.php --verify    # read-only live check
  # fresh install / throwaway DB: load the canonical files, in this order —
  #   database.sql (DDL) first, then database_seed.sql (data)
  # `seed_database.php` is not usable for this — see the known-broken CLI note in Notes.
  ```
  Migration scripts `include` `application/helpers/*_helper.php` directly and must be CLI-safe (pure functions, `function_exists()` guards). Their DB-config loader must follow the CI3 order **`$active_group` → `default` → first group** (pattern in `scripts/migrate_106/112/114_*.php`): `application/config/database.php` defines only `local`/`dev`/`live`, so a loader that reads `$db['default']` alone aborts with `[FATAL] Cannot read DB credentials` (Notes) — and `DB_*` env overrides cannot rescue it, because the failure happens while loading the config, before any connection.
- **Testing:** **there is no app test suite.** `composer.json`'s `test:coverage` script points at a non-existent `tests/` directory — do not claim it runs. Verify flows over HTTP (`curl`/browser, expect 200/302/303 + JSON envelope) against a **throwaway DB** built from the canonical files, never against `db_webtable`:
  ```bash
  # 1) scratch schema+seed (statement splitter needs quote/comment awareness:
  #    no `mysql` CLI is guaranteed, and database_seed.sql re-applies legacy
  #    ALTERs, so duplicate column/key errors (1060/1061) are expected+tolerable)
  # 2) run the app against it with the env overrides above
  # 3) drive real endpoints (login/CAPTCHA via /tmp harness) — not model re-implementations
  # 4) drop the scratch DB afterwards
  ```
  Fixtures stay in the repo when they encode a scenario: `scripts/seed_milestone_test_account.php` (leader + N downlines for the team-milestone matrix; `--downlines=N`, `--product=paid|trial|mixed`, idempotent, self-cleaning phone range `0812999900xx`; renamed from `seed_wage_test_account.php` by plan/119). Plan summaries in `plan/` record the per-change verification matrix to reproduce. **Gotcha:** `audit_i18n_hardcoded.php` walks **all of `application/**`** (not just views/controllers), so runtime artifacts such as `application/logs/*.php` can produce false findings — clear local runtime logs before running the gate.

## Architecture

- **`application/core/MY_Controller.php`** — base for member controllers. Fixed statement order after `parent::__construct()`, do not reorder: **① `maintenance_gate()`** (plan/95) → **② `SET time_zone = '+07:00'`** WIB pin (M2, first DB statement, forces lazy connection) → **③ `i18n_apply()`** (plan/94 F1) → **④ login guard** (`user_id`, redirect `login`; `auth` exempt) → **⑤ lazy sweeps + reads**: re-read user row (ban lockout / forced password change) → `Rental_model::expire_user_rentals()` (M3) → `Wallet_model::expire_user_deposits()` (plan/102) → `Wallet_model::get_balance()` → `Notification_model` counts. Injects `global_balance`, `global_unread_count`, `global_notifications`.
- **Controllers (member):** `Auth` (register/login/logout/change_password + native SVG CAPTCHA + phone normalizer; `auth/refresh_captcha` AJAX), `Home`, `Marketplace`, `Rentals` (checkout/claim), `Wallet` (**`index`, `topup`, `pay`, `confirm_payment`**, `simulate_payment`, `withdraw`, `process_withdraw`, `simulate_wd_approve`, `bind_bank`), `Team` (affiliate hub + `promoter_claim`, `claim_milestone` — plan/119; `claim_wage` and `claim_level1` **removed** — plan/119/120), `Checkin` (daily check-in `claim`, POST+AJAX-only, plan/112), `Rewards` (**Lucky Spin** — `index` page + `spin` POST+AJAX-only, plan/121, routes `lucky-spin` / `lucky-spin/spin`), `Profile`, `Help`, `Notification` (history page), `User` (`read_notifications` AJAX), `Lang` (dual-language switcher, extends `CI_Controller` so it works pre-login).
- **Controllers (admin):** `Admin` + `Admin_auth`, cloaked login at `/control-panel` (route `'control-panel' => 'Admin_auth/login'`), guarded by `admin_id` session (never shared with `user_id`). `Admin` also exposes queues/CRUD: deposits approve/**decline**, withdrawals, `promoter_claims`, `products` (+`create`/`update`/`toggle_status`), `ewallet_providers` (+`create`/`update`/`toggle_status`), `settings`/**`qris_settings`**/`financial_settings`, users (`user_detail`, `update_user`, `toggle_ban`, `toggle_promoter`, **`toggle_wd_lock`** — plan/117, `inject_balance`, `inject_rental`, `cancel_rental`, `adjust_time`, `reset_password`, `reset_ewallet`, `create_user`), **`lucky_spin`** (GET+POST, plan/121 — audit `admin_update_spin_wheel`), `toggle_registration`, `toggle_maintenance`, `expire_expired_rentals`, `alerts_poll`, `audit`, `analytics`/`chart_data`/`user_xray`, `export_csv`.
- **Models — all DB access lives here** (no SQL in controllers/views). `Wallet_model` is the **sole writer of money and of `bank_accounts`** (`_post()` is the single credit/debit choke-point; `bind_user_ewallet()`/`unbind_user_ewallet()`/`reassign_provider_name()`/`get_user_ewallet()`); `Ewallet_model` is the sole writer of `ewallet_providers`; `Rental_model` owns checkout/claim/expiry/rebate (checkout performs the **dual-wallet split** — checkin wallet first, remainder from main, plan/118); `Promoter_model` owns omzet-burn claims; `Admin_model` owns admin queues/CRUD/`get_alert_counts()`/`is_product_image_referenced()`; `Checkin_model` owns the daily check-in streak + the `CHK-{user_id}-{Ymd}` credit into the **`checkin` wallet** and the optional active-rental gate (plan/118); `Audit_model`, `Rate_limit_model`, `Notification_model`, `User_model` (the team-milestone engine: `get_milestone_config()`/`validate_milestone_settings()`/`get_milestone_status()`/`claim_milestone()`), `Product_model`, and **`Spin_model`** (plan/121 — sole writer of `users.spin_tickets`, `spin_ticket_grants`, `spin_results`; `award_ticket_for_first_paid_rental()` is a **caller-TX participant** invoked from `Rental_model::checkout_rental()` step 7b, while `spin()` owns its own money TX).
- **Ledger:** `wallet_ledger` is the **sole authoritative transaction ledger** — immutable `credit`/`debit` rows with deterministic `transaction_id` (`ROI-{rental_id}-D{n}`, `RBT-{rental_id}-L{tier}`, `CHK-{user_id}-{Ymd}`, `MSB-{user_id}-T{target}` — plan/119, `SPIN-{spin_results.id}` — plan/121, `RENT-{product_id}-{YmdHis}[-CHK|-MAIN]`, …). **plan/118:** every row also carries **`wallet_type ENUM('main','checkin')`** (DEFAULT `'main'`) — balances are per wallet and the **withdrawal path only ever reads `main`**. The legacy double-entry `transactions` table was decommissioned (M6, plan/68–69). All money moves run inside ACID transactions (`trans_begin/commit/rollback`) with a `SELECT … FOR UPDATE` anchor on `users`; balance = `SUM(credit) − SUM(debit) WHERE wallet_type = ?` via `Wallet_model::get_balance()` / `get_checkin_balance()` / `lock_and_get_balances()`.
- **Helpers are choke-points** (pure, `function_exists()`-guarded) — one source of truth per rule: `i18n_helper` (language resolution/application), `maintenance_helper` (gate + JSON parity detection), `captcha_helper` (SVG alphabet/render), `product_image_helper` (basename allowlist + `null` fallback contract), `wa_group_helper` (WhatsApp invite canonicalization), `ewallet_helper` (phone normalize/validate/mask), `referral_helper` (invite-code normalize/validate/prefill precedence), `withdrawal_amount_helper` (gross/fee/**net** resolution — net is always the displayed primary, plan/109), `withdrawal_fee_helper` (fee-tier validation/normalization/json, plan/110), `team_milestone_helper` (tier CSV/JSON codecs + admin limits, plan/119), `spin_wheel_helper` (wheel segment/odds/expected-value codecs + `spin_wheel_pick()` weighted CSPRNG pick, plan/121), `api_helper` (JSON envelope), `ratelimit_helper`. All are autoloaded except `api`/`ratelimit`/`captcha` (loaded on demand).
- **Views:** member pages use `templates/header.php` + `templates/bottom_nav.php`; admin uses `admin/templates/*`. Member header holds **exactly three groups — Brand, Balance Pill, Notification Bell** (plan/100); Language/Theme controls live on the Profile page ("App Preferences"). Mobile-first `max-w-[480px]` shell. **Lucky Spin** (plan/121) renders `views/rewards/index.php` plus a dashboard inline card and a FAB inside the `inset-x-0 bottom-20 z-40` layer (`max-w-[480px]` shell, below bottom-nav `z-50` and toasts `z-[60]`); the header and the Golden-5 bottom-nav are untouched by it.
- **Admin real-time alert center (plan/94 F2):** `GET /admin/alerts/poll` → `Admin::alerts_poll()` → `Admin_model::get_alert_counts()`; client in `views/admin/templates/footer.php` (`window.AdminAlerts`, 25 s polling, pause when hidden, chime only when `total_urgent` rises, `Cache-Control: no-store`, no audit row).

## Conventions & Standards

- Every PHP file starts with `defined('BASEPATH') OR exit('No direct script access allowed');`.
- **SQL only in models**, with bound params (`$this->db->query("… ?", [$id])`); query builder is acceptable (see `Admin`). No SQL in controllers or views (roadmap rule 2).
- **Dual-auth hard separation:** `user_id` vs `admin_id` sessions — never shared; admin routes redirect to `control-panel` when `admin_id` is missing.
- **API responses (mandatory, M9/P7 — plan/76–77):** every AJAX/JSON endpoint responds through `application/helpers/api_helper.php` (`api_success()` / `api_error()`) using the canonical envelope `{success, message, data, code?, errors}` **plus** root legacy keys where the frontend still reads them — never a hand-rolled `{success,…}` / `{error,…}` shape. AJAX 404/error/exception responses are normalized to clean JSON by `application/core/MY_Exceptions.php` (`_wants_json()`), so `fetch().json()` never parses HTML.
- **Integer IDR discipline (mandatory, M8 — plan/74–75):** validate monetary inputs server-side against `^[1-9][0-9]*$` before any model call; all credits/debits pass the single `(int)` choke-point + positivity assertion in `Wallet_model::_post()`; fee arithmetic uses `intdiv()` — never float division. MySQL keeps `DECIMAL(15,2)` for compatibility, but `get_balance()` / `lock_and_get_balance()` return `(int)`.
- **Money display:** PHP `number_format($val, 0, ',', '.')` with `Rp ` prefix; JS `Intl.NumberFormat('id-ID', { style: 'currency', currency: 'IDR', maximumFractionDigits: 0 })`. **Never** put money/numbers in the language dictionaries (L6; gate P3 enforces).
- **i18n rules:** member copy goes through `lang('<key>')`; EN and ID dictionaries must stay **1:1 with identical key sets (currently **669 each** — verified by `grep -cE "^[[:space:]]*\$lang\["`, do not trust the historical counts below)** and identical values are forbidden outside the auditor's allowlist. Dynamic JS strings are passed via `window.SYNAPSE_I18N`. Admin copy is Indonesian-only (L1) — never route admin through `i18n_apply()`. Run both `scripts/audit_i18n_*.php` gates after any copy change.
- **Route registration:** add an explicit `$route[...]` in `application/config/routes.php` for every new pretty URL **and for multi-segment sub-paths** (`translate_uri_dashes = FALSE`); otherwise CI3 maps the extra segment as a method argument. One-off AJAX methods (`auth/refresh_captcha`, `admin/toggle-ban`, `admin/reset_ewallet/{id}`) intentionally work as direct method URLs.
- **Schema/state machine changes are two-file changes:** `database.sql` (canonical DDL, with a migration note for live) **and** `database_seed.sql` where seed rows are involved, plus an idempotent `scripts/migrate_<NNN>_*.php`. Verify live with `--verify`.
- **Business state machines (see `docs/1_PRD.md` before touching money):** deposit `pending → waiting_approval → success` with `failed`/`rejected`/`expired` retention branches (plan/102: unique 3-digit code 100–999, `reserved_code_key` UNIQUE, expiry window default 60 min, credit = **principal + code** with the fee withheld, one live deposit per user); single pending withdrawal; withdrawal window **Mon–Sat 07:00–19:00 WIB**; integer fee tiers in `application/config/withdrawal_fees.php` with `system_settings` overrides (half-open `[min, max)` tiers — boundary amount takes the cheaper tier).
- **E-wallet payout contract (plan/106):** `bank_accounts` structure is frozen — `bank_name` = provider name from the catalog, `account_number` = canonical e-wallet phone (`^08[0-9]{8,11}$`), `account_holder` = owner name, `is_primary` = **active-binding flag** (`1` bound, `0` archived). Admin reset **archives, never deletes** (FK `fk_withdrawals_bank` is `ON DELETE RESTRICT`). Withdrawals verify ownership + binding status again inside the TX (`no_ewallet`).
- **Helper-first rule:** when you add a cross-cutting rule (validation, normalization, formatting, external-link handling), put it in a single `application/helpers/*_helper.php` choke-point and call it from controller/view/admin/CLI — do not re-implement inline.
- **Plan discipline:** work on per-phase branches per `docs/3_ROADMAP.md`; commit messages in Indonesian; keep `plan/NN_*_PLAN.md` + `plan/NN_*_SUMMARY.md` as the authoritative change record and refresh `docs/` when an invariant changes.
- **Framework compatibility rule (PHP 8.3):** the CI3 pagination root fix at `system/libraries/Pagination.php` (~`:526`, `(string)` cast so `ctype_digit(null)` is never hit when the `per_page` query segment is absent) is **required on PHP 8.1+ and must never be reverted** by a framework sync/upgrade (plan/80 follow-up). `application/config/mimes.php` **must** keep `'webp' => array('image/webp')` or `Upload::is_allowed_filetype()` rejects every WebP (plan/104). Reward amounts are **never** re-inlined: milestone tiers are **admin-configurable** (plan/119 — `system_settings.team_milestone_tiers`) and Lucky Spin segments likewise (plan/121 — `system_settings.spin_wheel_segments`); the old `User_model::LEVEL1_BONUS` const pattern was **deleted** with the feature (plan/120). Any new agency/referral reward must live in `system_settings` + a `application/config/*.php` fallback, never as a const or a literal in a view.

## Agent Guardrails & Operating Rules

**Always**
1. `php -l` every new/modified PHP file before declaring done.
2. Run both `scripts/audit_i18n_*.php` gates whenever member copy, views, or `application/language/**` change — both must exit 0.
3. Add/keep the `$route[...]` entry for any new URL (including sub-segments) and register non-obvious AJAX endpoints explicitly.
4. Keep SQL in models, money moves inside a TX with `FOR UPDATE`, and every status flip conditional (`WHERE status='pending'` + `affected_rows() === 1`, M4).
5. Write an `Audit_model` row for every admin state change; read-only endpoints (`alerts_poll`) must **not** audit (A1).
6. Keep CLI scripts idempotent with `--dry-run` default and exit codes 0/1/2, and mirror any DDL into `database.sql`.
7. Report the verification you actually ran (command + observed result). Never claim a test suite ran.

**Never**
1. Never edit anything under `system/` except the pinned `Pagination.php` fix; never revert that fix or the `mimes.php` webp entry.
2. Never write SQL in a controller or view; never bypass `Wallet_model::credit()/debit()/_post()` or `Ewallet_model` to mutate money/catalog rows.
3. Never call `i18n_apply()` (or load `app_lang`) from admin code; never localize money/numbers; never hardcode member copy.
4. Never hand-roll JSON envelopes; never let an AJAX path return HTML.
5. Never hard-delete: GPU products, e-wallet providers, bank bindings, or ledger rows (archive/toggle instead).
6. Never commit secrets, a `live` `$active_group`, or a production `base_url`; never re-introduce the purged external CAPTCHA (M8).
7. Never touch `uploads/qris/*`, `uploads/products/*`, or `backups/*` as tracked content — only the `index.html` placeholders are tracked.
8. Never park scratch scripts, probes, or generated output in the repo — use `/tmp` and clean up.

**Sensitive / high-blast-radius files** — change with care and re-verify live behaviour: `application/config/database.php` (credentials), `application/config/config.php` (`base_url`, `encryption_key`, CSRF/session), `application/core/MY_Controller.php` (statement order is load-bearing), `application/models/{Wallet,Rental,Promoter,Admin}_model.php`, `application/config/routes.php`, `database.sql` / `database_seed.sql`, and `scripts/migrate_104/105/106_*`.

**Definition of done:** every modified PHP file lints clean; both i18n gates exit 0 when copy changed; the flow is exercised over HTTP (200/302 as expected) or via the plan's CLI harness; DDL changes exist in both `database.sql` and an idempotent migration that has been re-run to prove a no-op; `plan/NN_*_SUMMARY.md` records the change with its evidence; the final diff contains only intended changes.
